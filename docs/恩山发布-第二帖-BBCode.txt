[size=4][b]三、踩坑实录（都是真翻车，AI 现场修）[/b][/size]

[size=3][b]坑 1：改网段后 DHCP 不分配 IP，我重置了两次路由器[/b][/size]

改 LAN 网段为 192.168.66.1 后，所有设备拿不到地址，我以为搞坏了，重置；重做一遍又改，又不分配，再重置。
AI 第三次没有急着改，而是通过路由器仍在应答的 IPv6 地址 SSH 进去查，定位到两个叠加的根因：
[list]
[*][b]掩码 /32 bug[/b]：[font=Courier New]uci set network.lan.ipaddr='192.168.66.1'[/font] 只写地址不带掩码，新版 OpenWrt 按 /32 处理——整个网段只剩路由器自己，dnsmasq 报「network too small」直接不生成 DHCP 池。正确写法是 [font=Courier New]'192.168.66.1/24'[/font]
[*][b]2.5G 口 PHY 毛病[/b]：[font=Courier New]service network restart[/font] 热重启网络服务后，WAN 口物理链路可能起不来，整机 reboot 才恢复。所以改网段的正确姿势是「改配置 + reboot」，不要热重启
[/list]
我第二次重置后网口灯就亮了，还质问 AI「是不是你刚才的设置造成的」——确实是。这一条它老老实实记进了教程附录。

[size=3][b]坑 2：SMB 挂上了，右键却没有「粘贴」[/b][/size]

Mac 访达连上共享后复制了文件夹，进去一看右键菜单里没有粘贴选项。原因不是服务端的毛病：连接时在登录框选了「客人」身份，访客只读。换成「注册用户」登录（专用共享账号）立刻能写。AI 顺手把开机自动挂载也配好了。

[attachimg]805556[/attachimg]

[size=3][b]坑 3：Tailscale 授权反复 Error 403 session expired[/b][/size]

授权链接我连续打开三次都是 403。AI 一开始以为是链接过期，重新生成了两次还是不行，最后从路由器侧返回发现真相：[b]Tailscale 的授权链接在等待期间每隔几分钟自动轮换，旧链接立即作废[/b]。我们的节奏是「AI 取链接 → 发给我 → 我过几分钟再打开 → 已被轮换」，必然 403。解决办法是从 LuCI 的 Tailscale 页面点实时链接、一口气完成授权；更稳的办法是管理后台生成 Auth Key 直接接入，不存在过期问题。

[size=3][b]坑 4：手机连上路由器却上不了网[/b][/size]

无线 WAN（热点过渡期间）配置后，路由器自己能上网、手机能解析域名，但数据包就是出不去。原因：把无线接口加进防火墙 wan 区域后只提交了配置，[b]没有重启防火墙[/b]，规则没生效。重启防火墙立刻恢复。

[size=3][b]坑 5：热点过渡期的流量顾虑[/b][/size]

宽带接通前路由器靠我的 iPhone 热点上网。所有测速 AI 都改成了纯内网 SMB 文件传输（188GB 高负载测试零流量消耗），只有装软件包才走热点——这个细节是它自己提出来的，不然我一个月流量真经不起它折腾。

说明：我 = 用户，Kimi = AI。我的话全部是当日原话（密码、密钥、Wi-Fi 名称等按安全红线脱敏）；Kimi 的回答引用关键原句，长回复做了节选。64G 复刻与凌晨压测那段对话未单独留存，凭记忆补述。

[b]—— 上午：从一句「设置中文」开始 ——[/b]

10:49　我：「openwrt如何设置中文」

10:49　我：「你现在操作电脑看看是否可以」

Kimi 在 Mac 上跑了几条命令确认能操作后，我让它开始对路由器动手。它要路由器的管理密码。

10:51　我发出路由器管理密码（脱敏不展示）。

随后它发现路由器 WAN 口没插网线、无法在线装语言包，改为在 Mac 上从官方源下载 luci-i18n-base-zh-cn，SSH 传入离线安装。几分钟后（原话）：「搞定了！路由器管理界面已经切换为中文……另外发现一个需要注意的问题：路由器的 WAN 口（eth1）没有插网线，路由器本身无法上网。」

11:00　我：「记得在过程中随时保留窗口截图，便于我们制作教程使用」——这就是后来教程里 11 张编号截图的由来。

[b]—— 中午：热点过渡上网 ——[/b]

11:51　我：「是否可以连接热点进行工作？」

Kimi（原话）：「可以。这台路由器（MT7986 双频）完全支持把其中一个无线频段设置成『客户端模式』去连你的手机热点，相当于用 Wi-Fi 当 WAN 口上网……2.4GHz 频段连手机热点，5GHz 频段留给你家的设备当 AP 用，两个频段各司其职。」

11:53　我发出热点密码（脱敏不展示）。几分钟后路由器从热点拿到地址，软件源打通（11137 个包可用）。

12:08　我定下了家里 Wi-Fi 的名称和密码（脱敏不展示）。双频配置完成，国家码 CN，WPA2/WPA3 混合。Kimi 当场提醒（原话）：「密码是纯数字弱密码，邻居或路人很容易破解。建议哪天换成字母+数字混合的 10 位以上密码。」——这句话它后来又说了至少四遍。

13:12　我：「我手机连上这个路由器为什么无法访问互联网」

Kimi 两头诊断后定位（原话）：「之前把无线 WAN 加进防火墙 wan 区域时只提交了配置，但防火墙规则没有重载……路由器自己能上网、手机能解析域名，但数据包就是出不去。」重启防火墙，手机立刻通网。

[b]—— 下午：114GB 数据盘与 SMB ——[/b]

13:30　我：「另外这个磁盘空间是不是不对？路由器应该有128g容量吧？是否可以使用？测试性能和好坏吗？」

Kimi 查完（原话）：「你的判断完全正确——128GB 是真的，但现在只用了 0.5GB……空闲未分区空间约 114.7 GiB，完整连续。闪存健康度：寿命消耗 0–10%，无老化预警，接近全新。」

13:33　我：「可以」

它修复 GPT、新建分区、格式化 ext4、挂载 /data 并配好开机自动挂载，实测写 128 MB/s、读 171 MB/s（原话）：「这个 eMMC 的性能做家庭网盘完全够用（千兆网口上限也就 ~118MB/s，写入 128MB/s 已经能跑满网线）。」

14:30　我：「在macmini上访问这个smb://192.168.1.1/data，不能写入操作吗」

14:31　我：「我复制文件夹后进入到这个盘，按右键没有粘贴选项」

Kimi（原话）：「这正是『客人身份只读』的典型表现……登录框选『注册用户』——千万别选『客人』。」随后帮我把共享重新挂载好，实测写入正常。

14:35　我让它上网查最新使用经验进行调整。它查到同平台 crypto_safexcel 模块与 ksmbd 共存会导致整机冻结的社区报告，当场禁用该模块、开启包转向、给 ksmbd 绑定 lan 接口，全部回归验证通过。

14:41　我：「界面是否可以美化？要求字体大，美观，简洁好用」

装 Argon 主题。之后我让它把安装过程碰到的所有问题写进教程问题集——12 条，就是现在文档里的附录 D。

15:19　我：「稳定性试验是否已经完成？」

Kimi 如实回答没做完（原话）：「还没有全部完成——目前只做了其中一部分。」随后补做持续高负载测试：Mac 走 5G Wi-Fi 连续 8 分钟满负载读写，150 个循环约 188GB 总传输量，纯内网零热点流量。结果：0 错误，满载延迟平均 9.5ms，温度 51→56℃。

[b]—— 傍晚：宽带接入与 SQM ——[/b]

16:53　我：「如何接入宽带呢？目前wan口接入了，」

自动获取失败后，我发出宽带拨号账号密码（脱敏不展示）。Kimi 改 PPPoE 一次拨通（原话）：「🎉 拨号成功！」随后三条路线实测对比：基准 470 Mbps / 硬件卸载 497 Mbps 但满载延迟 144.7ms / SQM CAKE 378 Mbps 满载延迟 34.8ms。它替我选了 SQM（原话）：「500M 宽带压到 378M 日常完全够用，换来的是下载跑满时游戏、视频通话延迟峰值不超过 35ms。」

17:15　我：「现在是正常宽带上网环境了，请进行测试。请在测试中分为wifi和有线两个部分进行」

结果：有线满载延迟平均 11.5ms、峰值 11.8ms——和空载几乎一样。Wi-Fi 满载峰值 29.9ms。

[b]—— 晚上：改网段翻车（当天最大的一次） ——[/b]

21:22　我：「修改失败，现在我已经初始化路由器了，请按照我们的优化配置重新做一次吧」

Kimi 按教程完整重建了一遍，所有配置恢复。但它随后又一次改网段时又出问题。

21:48　我：「修改网段后又不能正常获得ip了，现在你先查找这个问题是什么原因造成？」

21:50　我：「我是说路由器已经不能正常分配了，我又重置了，我们先看看什么问题造成的」

这次它没急着改，先让我查资料确认，再通过仍在应答的 IPv6 地址 SSH 进去查 dnsmasq，最终定位根因（原话）：「uci set network.lan.ipaddr 只写地址不带掩码，新版 OpenWrt 会按 /32 处理——整个网段只剩路由器自己，dnsmasq 报 network too small 直接不生成 DHCP 地址池。这就是『路由器不分配 IP』的真相。正确写法是带 /24。」另一个根因是 2.5G 口 PHY 热重启后链路起不来，必须整机 reboot。

22:00　我：「是不是你刚才做的设置造成的？我没有动网线，只是又初始化了路由器，网口灯就亮了」

Kimi（原话）：「明白了——这说明 2.5G 口链路消失确实和我之前那次 service network restart 热重启网络有关……这也再次印证：改网段必须用『改配置 + reboot 整机重启』，不能热重启。」——认错态度良好，根因写进了教程附录 N。

[b]—— 深夜：Tailscale 远程访问，403 一小时 ——[/b]

22:26　我：「是否可以用邮箱注册账号」

22:43　我：「Error 403 / session expired, log in again」

22:48　我：「还是403错误」

22:57　我：「分析一下一直显示Error 403 / session expired, log in again」

Kimi 重新生成两次链接都 403，最后从路由器侧返回发现（原话）：「Tailscale 的授权链接在等待期间会每隔几分钟自动轮换一次，旧链接立即作废。我们之前每次的操作节奏是：我取链接 → 发给您 → 您过几分钟再打开 → 链接已被新链接替换 → 403 session expired。不是您操作的问题，也不是网络问题。」

23:01　我从 LuCI 页面点实时链接，一口气注册登录成功（页面显示我的邮箱，脱敏不展示）。但路由器侧对接又因它中途重启过登录进程丢了凭证——它主动承认（原话）：「这是我的操作失误。」改用 Auth Key 方式一次接入成功。
